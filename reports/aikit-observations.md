# AIKit observations during Traceglass setup

## 2026-11-22

- `aikit new` created a separate Git repository and task memory, then left local brand candidates untracked. The project ledger and guidelines provide a durable task and architectural contract.
- The new software scaffold included `demo.py` and `inventory.py` even though this project is Rust-only. These are generic placeholders, not a Rust implementation. A stack-aware scaffold would avoid generating incompatible source files.
- `ui init` reported UI kind `web` for a manually declared terminal surface. The project UI identifier was corrected with `ui-id --set yes --kind cli`. The UI contract must be committed before `ui begin`, including when recovering with `--since HEAD`.
- The AIKit root reports inbox already exceeded its stated cap at startup. This project retains its requested observations here, separately from that local-only inbox.
- The default MSVC toolchain could not find `link.exe`; the already-installed GNU toolchain and GCC successfully ran the two initial Rust tests. This is a host setup issue, not an AIKit defect.
- The first project gate failed hygiene as inconclusive because it scans Python and web assets, not Rust, and failed compatibility because the scaffold's commands invoke its Python placeholders. This prevents a Rust-only project from passing the default project gates without a supported adaptation. The documentation check also requires specific cold-start and tree headings; that finding is project documentation work.
- The built-in hygiene gate cannot be replaced through project gate overrides (`scripts/project_gates.py`); adding a dummy scannable file would manufacture evidence rather than check the Rust code. The compatibility record can declare non-Python commands, but those commands must exercise real program behavior and deterministic replay.
- On the next session, `sync_principles.py --involved` refused because the AIKit native DLL was older than its Rust sources. Its diagnostic recommends rebuilding the native library; until then the involved-principle lookup was not available. This is a freshness refusal, not evidence of a defect in the parser itself.
- Concurrent uncommitted changes in the AIKit checkout appear to add Rust source hygiene scanning. They belong to another workstream and were not modified or relied upon here; their completion and verification remain unknown.
- AIKit commit `df4bab81` subsequently added Rust text hygiene support; the Traceglass hygiene gate now passes. Its scope is text hygiene, not a proof of Rust semantics. Traceglass replaced the scaffold compatibility commands with a Rust inventory and deterministic scripted comparison; AIKit's compatibility gate passes against those commands.
- UI initialization, begin, verify, and finish repeatedly set the manually declared CLI UI kind to `web`, despite a manual terminal surface. `ui-id --set yes --kind cli` restores it. The UI workflow accepted a Rust test command and the terminal surface once its contract was committed; the agent reviewed a real scripted terminal run.
- `ui begin --since HEAD` stored the literal string `HEAD`, after which `ui verify` incorrectly reported that the unchanged baseline had moved. `ui abort --force` preserved the work and a full commit hash allowed a new review. Resolving a ref to its commit when beginning would avoid the false refusal.
- Restoring source and test files with their original timestamps caused Cargo to reuse old artifacts: a test filter ran zero tests and the terminal displayed old behavior. The UI fast proof accepted the stale Cargo result. Updating the files' modification times forced recompilation; the restored four UI tests and a real long-value comparison then passed. A clean build or content-based build freshness check would provide stronger evidence after timestamp-preserving restores.
- `aikit chore` refused a documentation-only change because `reports/architecture-audit.md` is outside its recognized documentation locations. A checkpointed task was needed for that Markdown update; recognizing project report Markdown as documentation would make the classifier more accurate.

## 2026-11-22 (second session, continuing the project)

- The Rust toolchain gap is confirmed and broader than the first gate: with the MSVC default, `cargo test`, `aikit.py check traceglass` (compat gate) and even `aikit.py ui begin` (its fast UI proof) all fail with `link.exe not found`. Exporting `RUSTUP_TOOLCHAIN=stable-x86_64-pc-windows-gnu` makes all three pass and gives `5/5` project gates. There is still no project-level field to declare this, so every host and every agent must rediscover it.
- `ui begin` and `ui verify` again report `UI identifier: has_ui=True kind=web` for the manually declared CLI surface. The reset to `web` first seen during setup still happens on a later session; `ui-id --set yes --kind cli` remains the only durable correction known here.
- `ui verify` requires explicit `ui allow-cross` for `src/main.rs` and `ui allow-test` for two new test files. Recording the reason works well, but the 200-added-line budget counts helper and regression tests against the same surface limit; a small CLI feature had to be compacted to fit rather than kept at natural readability. Separate documentation/test budgets or an explicit "tests do not count" rule would make the shield measure the UI change instead of its proof.
- `aikit.py check` still prints a warning about the AIKit root reports inbox being over its 20-file cap (64 files) on every project check, although this project's own inbox is 2/20. This session placed verified findings in the root `reports/combined/traceglass.md` to avoid growing the inbox.
- The project ledger still shows the completed `prefix-alignment` task as "active", owned by `codex:traceglass` with an unexpired lease. Opening a new task with `aikit.py checkpoint` succeeded without a take-over, but the status banner remains yellow and could mislead a cold-start agent into treating finished work as in flight.
- Positive: the hygiene scan now handles the changed Rust files cleanly (`No hygiene findings`), and the UI review workflow (begin → allow-cross/allow-test → verify → agent review of the running binary) completed without touching AIKit rule files.
